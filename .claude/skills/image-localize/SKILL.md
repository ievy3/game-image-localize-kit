# 그림 글자 한글화

이 스킬은 **그림 글자 한글화 키트**(README 제목 「그림 글자 한글화 키트 — Codex CLI · Claude Code」)로 작업한다. 규칙의 원본은 키트의 `IMAGE_RULES.md` — **작업 전에 반드시 읽고 그대로 따른다.** 아래는 순서와 손이 갈 곳만 적은 요약이다.

이 스킬은 Claude Code 와 Codex 어느 쪽에서 불러도 같다. 배경 글씨·디자인 글씨는 어느 쪽에서든 `imgcodex` 가 **Codex CLI 를 따로 띄워** 처리한다 — 그래서 Codex CLI 설치·로그인은 늘 필요하다 (`IMG login`).

답은 사용자가 쓰는 말로 한다.

## 지켜야 할 것
- 그림에 넣을 한국어는 사용자가 준 요청본이거나, 네가 번역해 사용자가 승인한 것만 쓴다. 어느 쪽인지 작업 시작 때 묻는다 (3-1).
- Codex 계정은 사용자 본인 것. 로그인은 사용자가 `codex login` 으로 직접 한다. 너는 비밀번호·키를 묻거나 입력하지 않는다. 확인은 `python <키트>/tools/img.py login` 의 한 줄만 전한다.
- 경로·폴더 이름을 짐작해 박지 않는다. 키트와 작업 폴더를 찾거나 묻는다.
- 원본(`src/`)은 고치지 않는다. 결과는 원본과 같은 크기·이름의 PNG.
- 갈래 분류표·계열 표본은 **사용자 승인** 뒤에 다음으로 간다.
- 배경 글씨의 지우기가 깨끗한지는 `codex_check.csv` 의 찌꺼기 수치가 가른다. 네 눈으로 「깨끗하다」고 보증하지 않는다.
- 글꼴은 키트의 `fonts/` 에 있는 **SIL OFL 글꼴이면 무엇이든** (`FONTS.md` 목록은 추천일 뿐). 글꼴 폴더에 OFL 라이선스 파일(OFL.txt 등)이 있는지 보고, 없으면 쓰기 전에 사용자에게 묻는다. 시스템 글꼴(바탕·굴림·맑은 고딕 등)은 쓰지 않는다.
- 그림을 고치거나 받을 때마다 `imgview` 비교 HTML 을 만들어 사용자에게 경로를 알린다.

## 1. 키트와 작업 폴더 찾기
- 키트: `tools/img.py` 와 `IMAGE_RULES.md` 가 있는 폴더. 지금 폴더나 위 폴더에 없으면 사용자에게 묻는다. 이하 `IMG = python "<키트>/tools/img.py"`.
- 작업 폴더: 게임마다 하나 (이름·위치 자유). 기본 구성 `src/ grids/ bundles/ ko/ review/` (README 「작업 폴더」). 없으면 사용자와 정해 만든다. 원본 PNG 를 `src/` 에 넣는 것은 사용자(또는 그 기종의 추출 도구)가 한다.
- 작업 폴더에 `IMAGE_RULES.md` 의 「이 게임의 값」을 옮겨 적을 `IMAGE_NOTES.md` 를 두고, 정한 값(투명 표시색·화면 범위·갈래별 개수·승인 날짜)을 적는다.

## 2. 글씨 있는 그림 찾기
- 그림을 직접 본다 (PNG 파일을 열어 보는 도구로). 투명 바탕은 `IMG imgdark --src src --out dark` 대조표로 다시 본다.
- 결과를 `IMAGES.csv`(file, 글씨 있음/없음, 메모)로.

## 3. 격자 파일
- 글씨 있는 그림마다 `grids/BOXES_<그림 이름>.csv`, 열 `file,x0,y0,x1,y1,kind,id,jp,ko,분류,grid,note`.
- 원본을 직접 보고 잰다. 큰 그림은 확대해 잘라 본다. 상자는 8px 격자 칸 경계에 맞추고, 외곽선·그림자·넘친 획까지 넣는다. 저작권·로고·영문은 `kind=keep`. 글자 옆에 붙은 아이콘·단추는 상자가 덮지 않게 하고 그 자리를 `keep` 상자로 넣는다 (덮으면 지우기가 그 그림까지 지운다).
- 디자인 글씨 상자는 효과(외곽선·그림자·튀어나온 획)까지 다 덮는다 — 덜 덮으면 Codex 가 상자 밖 그림까지 다시 그린다.
- 여러 줄은 `jp`·`ko` 에 `\n`(두 글자)으로 줄을 나눠 적는다. 줄 사이에 빈 행이 없을 만큼 붙은 줄은 줄마다 상자 하나로. 줄 앞 아이콘(□ 등)은 `keep`, 줄 상자는 아이콘 뒤부터.
- 좌표 확인용: `IMG imggrid --spec grids --src src --out bundles/_check --erase-only` 의 `grid/*.png` 를 보고 상자가 글자를 다 덮는지 본다 (확인 뒤 지워도 된다).
- 이 단계에서는 `ko` 를 비워 둔다 (다음 단계에서 정한다).
- `분류` 초안을 채우고 **사용자 승인**을 받는다 — `clear`(투명 글씨: 둘레가 투명해 지우면 빈자리만 남음) / `bg`(배경 글씨: 뒤에 그림이 있지만 보통 글꼴로 다시 쓸 수 있음) / `design`(디자인 글씨: 로고·손글씨·장식·효과) / `keep`(그대로 둘 글자). 배경과 디자인 사이가 애매하면 `design`. 격자 파일에는 이 넷만 적는다 (다른 값이면 도구가 멈춘다).

## 3-1. 번역문 — 먼저 묻는다
- **`ko` 를 네가 마음대로 채우지 않는다.** 격자 파일을 만든 뒤 사용자에게 묻는다:
  (가) 번역본(요청본)을 줄 것인가 / (나) 세션(너)이 번역하고 사용자가 승인할 것인가. 용어집·대사 번역본이 있는지도 묻고, 있으면 그 용어·말투를 따른다. 고른 쪽을 `IMAGE_NOTES.md` 에 적는다.
- 요청표 만들기: `IMG imgreq --grids grids --out 번역요청.csv` (열 `file, id, 분류, jp, 칸폭, 칸높이, 원문글자수, note, ko`).
  - (가): 이 표의 경로를 사용자에게 알리고, `ko` 를 채워 돌려받는다.
  - (나): 네가 `ko` 를 채운 표를 사용자에게 보여 승인받는다. 칸폭·원문글자수를 보고 칸에 들어갈 길이로.
- 받은(승인된) 표를 넣는다: `IMG imgreq --grids grids --apply 번역요청.csv`. `--check` 로 빈 칸이 없는지 본다.
- 렌더 중 칸에 안 들어가 말을 줄여야 하면(※ 표시) 줄인 문구를 사용자에게 확인받는다.
- `ko` 가 빈 clear·design 상자는 `imggrid`·`imgrender` 가 멈춘다. bg 는 Codex 에 맡길 때는 비어도 되지만 렌더 전에 채운다.

## 4. 갈래별 진행
**투명 글씨 (`clear`) — 직접 렌더**
- 키트의 렌더 함수 모음 `tools/imgrender.py` 를 쓴다 — 바닥부터 짜지 않는다. 계열(같은 모양의 그림 묶음)마다 `examples/render_series.py` 를 작업 폴더 `render/<계열>.py` 로 복사해 STYLE(글꼴 키·크기·fallback·자간·정렬·색·외곽선)만 고치고 돌린다. 맨 위 설명에 「원문이 어떤가 → 무엇으로 왜」를 적는다.
- `run()` 이 해 주는 것: 상자 안 글자 지우기(알파 0, 넘친 외곽선·그림자까지, keep 상자는 지킴) → 원본 잉크의 줄 위치·기준점 재기 → 그리기 → 칸을 넘으면 ±2px·작은 크기·좁은 자간 순으로 → 같은 그림은 한 크기 → `ko/` 에 저장, 상자마다 쓴 글꼴·자간 또는 「칸에 안 들어감」 출력.
- 원문 글자색이 위아래로 바뀌면(그러데이션) `grad='auto'`(원문에서 재서 그대로), 반투명 띠처럼 글자 화소의 알파가 일정하면 `ink_alpha=`. 원문 스타일을 빼먹지 않게 색·외곽선·그림자·그러데이션·반투명을 원문에서 하나씩 확인한다.
- 그림마다 특별한 손질(기울임·굵히기·팔레트 단계·불투명 바탕을 바탕색으로 비우기 등)은 계열 스크립트에 더한다. `text_mask`·`place`·`compose`·`erase`·`lines_of` 를 따로 불러도 된다 (imgrender 첫머리 설명).
- **원문 충실이 첫째.** 원문이 도트 글씨면 화소 글꼴, 매끈한 글씨면 벡터 글꼴을 원문 글자 높이로 — STYLE 에 `spec=('키', 'orig')` 와 `pixel=[화소 spec…]` 을 적으면 `run()` 이 원문(도트/매끈·높이)을 재고, 칸에 안 들어가면 자간 → 장평 → 작은 크기 순, 매끈한데 벡터가 뭉개지면 화소로 간다. 상자마다 「원문 15px 매끈 → NOTOB 16 장평0.9 15px」처럼 출력하니 **계열 표본 때 이 판정을 사용자에게 보여 확인**받고, 틀리면 `ink=`·`h=` 로 고친다. 원문 높이의 85% 아래(※ 표시)면 짧은 말을 먼저 찾는다. 계열은 `run_series(pack, 이름들, style)` — 원문 크기가 같은 글씨(같은 `_group` 또는 같은 상자 id)는 모든 그림에서 같은 글꼴·크기. 원문 크기가 다른 글씨는 묶지 않는다. 원본 스타일(색·외곽선·굵기)·정렬 기준점(±2px)을 맞춘다. 한글은 상자 안에만.
- `color='auto'` 는 밝은 글씨용이다. 어두운 글씨는 원본 잉크에서 잰 색을 직접 적고 `mode='alpha'`.

**배경 글씨 (`bg`) — Codex 가 일본어를 지우고 그 자리 배경을 살리면, 그 자리에 한글을 직접 렌더**
```
IMG imggrid --spec grids --class bg --src src --out bundles/bg_01
IMG imgcodex bundles/bg_01
```
- `bundles/bg_01/codex_check.csv` 를 읽어 그림마다 판정·까닭을 사용자에게 요약한다. 찌꺼기 수치는 그러데이션·다시 그린 그림·남긴 기호도 세어 깨끗한 배경을 불통으로 자주 잡고, 뭉개진 배경은 못 가린다 — 불통·통과 모두 `imgview` 로 보여 주고, 불통이지만 깨끗한 배경을 쓸지는 사용자가 정한다.
- 통과한(또는 사용자가 쓰기로 한) `result/` 배경 위에 투명 글씨와 같은 방법으로 한글을 렌더한다 — `run(..., cls='bg', start='bundles/bg_01/result')` (지우지 않고 그 배경에서 시작, 줄 위치는 원본에서 잰다). 불통 그림은 사용자에게 꾸러미(`bundles/bg_01.zip`)와 함께 알린다.

**디자인 글씨 (`design`) — Codex 가 완성 그림까지**
```
IMG imggrid --spec grids --class design --src src --out bundles/design_01
IMG imgcodex bundles/design_01
```
- 기계 검사는 크기·투명도·회색 상자만 본다. 한글 문구·모양은 판정(5)에서 본다.

`imgcodex` 는 오래 걸린다(그림 수에 따라 수십 분). 백그라운드로 돌릴 수 있으면 그렇게 하고 끝나면 알린다. 끝 코드 0 = 전부 통과, 2 = 불통이 남음, 3 = Codex 로그인 안 됨(사용자에게 `codex login` 을 안내). 다시 맡길 때는 `--mistakes <지난번에 틀린 것.txt>` 로 꾸러미를 새로 만든다.

## 5. 판정·표본
```
IMG imgview --orig src --result <결과 폴더> --boxes grids --title "<계열·회차>" --out review/<제목>.html
```
- 계열마다 한 장을 먼저 만들어 이 화면으로 보여 주고 승인받은 뒤 나머지를 한다.
- 보여 주기 전에 화면의 「칸 밖 변경」을 먼저 확인한다 — 단추·아이콘·빛번짐이 지워졌으면 keep 상자를 고쳐 다시 만든다.
- 판정 기준은 `IMAGE_RULES.md` §4. 흠 하나를 찾으면 같은 종류 전 장을 다시 본다.
- 사용자가 내려받은 판정 CSV(file, verdict, memo)는 `review/` 에 두게 하고 읽는다. 통과한 것만 `ko/` 로 복사한다.
- 게임 레이아웃 파일이 있으면 `IMG imgcells --layout … --orig … --result …` 로 칸 넘침을 본다.

## 6. 넘기기
`ko/` 의 PNG 를 게임에 다시 넣는 것은 그 기종의 도구가 한다. 넣은 뒤 다시 꺼내 원본과 견주고(팔레트 그림은 인코더를 거친 결과로), 빌드 화면을 보라고 알린다. 쓴 글꼴과 라이선스(OFL.txt)를 배포 꾸러미에 넣으라고 알린다.
